# REC Annotation Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-quality, local-first REC image annotation editor that preserves original-image bbox coordinates while supporting complete visual editing, history, validation, and TXT/JSON export.

**Architecture:** A React/TypeScript single-page application owns one normalized editor state. Pure domain modules parse, validate, transform, and serialize original-image coordinates; an SVG viewport renders the image and annotations through one shared transform and translates pointer input back into image coordinates. Browser file APIs keep data local, with standards-based download fallbacks.

**Tech Stack:** React 18, TypeScript 5, Vite 6, SVG, Vitest, React Testing Library, Playwright, plain CSS.

**Spec:** `docs/superpowers/specs/2026-09-03-rec-annotation-editor-design.md`

## Global Constraints

- Store every bbox in original image pixels; viewport scale and offsets must never enter persisted annotation data.
- Treat `label` as an arbitrary non-empty string. Never create category constants, dropdowns, or label-based identity.
- Give every imported or created bbox a stable, unique annotation ID independent of its label.
- Parse the first four TXT fields as coordinates, an independent final `0` as the reserved field, and all intervening text as the label.
- Keep all npm packages in project-local `node_modules` and npm cache in project-local `.npm-cache`; never modify Conda/base or global npm state.
- Support desktop Chromium/Firefox/Safari download behavior; use File System Access only as a progressive enhancement.
- Group a complete drag, resize, label edit, or numeric commit into one undoable transaction.
- Reject atomic imports containing any invalid non-empty line so current user data is never partially replaced.
- Use exact lockfile resolution in CI/startup through `npm ci`.

- [ ] **Step 3: Implement strict parsing and stable imported IDs**

Use the numeric grammar below so decimals and scientific notation work but `NaN` and `Infinity` do not:

~~~ts
const NUMBER = "[-+]?(?:\\d+(?:\\.\\d*)?|\\.\\d+)(?:[eE][-+]?\\d+)?";
const LINE = new RegExp(
  `^\\s*(${NUMBER})\\s+(${NUMBER})\\s+(${NUMBER})\\s+(${NUMBER})\\s+(.+?)\\s*$`
);

export function parseAnnotationText(text: string): ParseResult {
  const annotations: Annotation[] = [];
  const issues: ParseIssue[] = [];

  text.split(/\r?\n/).forEach((source, index) => {
    if (!source.trim()) return;
    const match = LINE.exec(source);
    if (!match) {
      issues.push({ line: index + 1, reason: "expected four coordinates and a label", source });
      return;
    }
    const x1 = Number(match[1]!);
    const y1 = Number(match[2]!);
    const x2 = Number(match[3]!);
    const y2 = Number(match[4]!);
    if (![x1, y1, x2, y2].every(Number.isFinite) || x2 <= x1 || y2 <= y1) {
      issues.push({ line: index + 1, reason: "invalid bounding box", source });
      return;
    }
    const tail = match[5]!.trim();
    const reserved = /^(.*\S)\s+0$/.exec(tail);
    const label = (reserved?.[1] ?? tail).trim();
    if (!label) {
      issues.push({ line: index + 1, reason: "expression cannot be empty", source });
      return;
    }
    annotations.push({
      id: `ann_${String(annotations.length + 1).padStart(3, "0")}`,
      bbox: { x1, y1, x2, y2 },
      label,
      reservedField: reserved ? "0" : null
    });
  });
  return { annotations: issues.length ? [] : annotations, issues };
}
~~~

The final return enforces atomic import: any issue empties the returned annotation list.

const coordinate = (value: number) => value.toFixed(2);

export function serializeAnnotationsTxt(annotations: readonly Annotation[]): string {
  if (annotations.length === 0) return "";
  return annotations
    .map(({ bbox, label }) =>
      [bbox.x1, bbox.y1, bbox.x2, bbox.y2].map(coordinate).join(" ") +
      " " + label.trim() + " 0"
    )
    .join("\n") + "\n";
}

export function serializeDocumentJson(document: AnnotationDocument): string {
  return JSON.stringify({
    image: document.image?.name ?? null,
    width: document.image?.width ?? null,
    height: document.image?.height ?? null,
    annotations: document.annotations.map(({ id, bbox, label, reservedField }) => ({
      id,
      bbox: [bbox.x1, bbox.y1, bbox.x2, bbox.y2],
      label,
      reservedField
    }))
  }, null, 2) + "\n";
}

- [ ] **Step 3: Implement pure bbox geometry**

Implement helpers using finite bounds and a `MIN_BOX_SIZE = 1`. `moveBBox` preserves width/height while limiting its origin. `resizeBBox` changes only axes named by the handle, clamps to `[0,width] × [0,height]`, and limits a moved side to one pixel before the fixed side. `bboxFromPoints` uses min/max and then `clampBBox`.

Use one axis helper so all eight handles obey the same invariant:

~~~ts
const clamp = (value: number, min: number, max: number) => Math.min(max, Math.max(min, value));

function resizeAxis(
  low: number,
  high: number,
  point: number,
  moveLow: boolean,
  moveHigh: boolean,
  maximum: number
): [number, number] {
  if (moveLow) return [clamp(point, 0, high - MIN_BOX_SIZE), high];
  if (moveHigh) return [low, clamp(point, low + MIN_BOX_SIZE, maximum)];
  return [low, high];
}

export function bboxFromPoints(a: Point, b: Point, bounds: ImageBounds): BBox {
  return clampBBox({
    x1: Math.min(a.x, b.x), y1: Math.min(a.y, b.y),
    x2: Math.max(a.x, b.x), y2: Math.max(a.y, b.y)
  }, bounds);
}
~~~

Use these exact formulas:

~~~ts
export interface Point { x: number; y: number }
export interface Size { width: number; height: number }
export interface ViewTransform { scale: number; offsetX: number; offsetY: number }

export function imageToViewport(point: Point, t: ViewTransform): Point {
  return { x: point.x * t.scale + t.offsetX, y: point.y * t.scale + t.offsetY };
}

export function viewportToImage(point: Point, t: ViewTransform): Point {
  return { x: (point.x - t.offsetX) / t.scale, y: (point.y - t.offsetY) / t.scale };
}

export function zoomAroundPoint(t: ViewTransform, anchor: Point, nextScale: number): ViewTransform {
  const imagePoint = viewportToImage(anchor, t);
  return {
    scale: nextScale,
    offsetX: anchor.x - imagePoint.x * nextScale,
    offsetY: anchor.y - imagePoint.y * nextScale
  };
}
~~~

- [ ] **Step 3: Implement safe local file helpers**

`partitionDroppedFiles` accepts MIME `image/*` or a recognized image extension and one case-insensitive `.txt`; extras go to `rejected`. `readTextFile` uses `file.text()`. `loadImageFile` creates one object URL, waits for decoded dimensions, rejects with `Could not decode image "<name>".`, and revokes the URL on failure. ~~~ts
export async function loadImageFile(file: File): Promise<ImageInfo> {
  const url = URL.createObjectURL(file);
  try {
    const image = new Image();
    await new Promise<void>((resolve, reject) => {
      image.onload = () => resolve();
      image.onerror = () => reject(new Error(`Could not decode image "${file.name}".`));
      image.src = url;
    });
    return { name: file.name, width: image.naturalWidth, height: image.naturalHeight, url };
  } catch (error) {
    URL.revokeObjectURL(url);
    throw error;
  }
}
~~~

- [ ] **Step 3: Implement progressive save APIs**

Add narrow ambient declarations for `Window.showOpenFilePicker` and `Window.showSaveFilePicker`. Use `Blob`, a temporary anchor, and same-tick cleanup for fallback download. Save stores a TXT handle only when one was obtained through the picker; a regular `<input type=file>` file cannot be overwritten and therefore downloads.

~~~ts
export async function writeTextToHandle(handle: FileSystemFileHandle, contents: string): Promise<void> {
  const writable = await handle.createWritable();
  await writable.write(contents);
  await writable.close();
}

export async function saveTextAs(contents: string, suggestedName: string, mime: string): Promise<SaveResult> {
  if (!window.showSaveFilePicker) {
    downloadText(contents, suggestedName, mime);
    return "downloaded";
  }
  try {
    const handle = await window.showSaveFilePicker({ suggestedName });
    await writeTextToHandle(handle, contents);
    return "saved";
  } catch (error) {
    if (error instanceof DOMException && error.name === "AbortError") return "cancelled";
    throw error;
  }
}
~~~
